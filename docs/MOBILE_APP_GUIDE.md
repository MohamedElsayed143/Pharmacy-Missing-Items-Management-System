# Pharmacy Missing Items Management System — Flutter Android Mobile Application

دليل وتوثيق تطبيق أندرويد المتكامل مع النظام المركزي لإدارة نواقص الصيدلية.

---

## 1. نظرة عامة على الهيكل المعماري (Architecture Overview)

يعمل تطبيق الهواتف الذكية (`pharmacy-mobile`) كعميل رسمي ثانٍ (Second Official Client) لنفس النظام المركزي المشترك مع تطبيق سطح المكتب (Desktop Application).

```
                      +------------------------------------------+
                      |         PostgreSQL Database (5433)       |
                      +--------------------+---------------------+
                                           |
                                           v
                      +------------------------------------------+
                      |       Node.js / Express / Prisma API     |
                      |            Socket.IO Server              |
                      +--------------------+---------------------+
                                           |
                     +---------------------+---------------------+
                     |                                           |
                     v                                           v
       +----------------------------+             +----------------------------+
       |   Desktop Workstations     |             |    Android Mobile App      |
       |  (Electron + React + Win7) |             |     (Flutter + Riverpod)   |
       +----------------------------+             +----------------------------+
```

### المبادئ الأساسية:
1. **قاعدة بيانات واحدة**: لا توجد قاعدة بيانات مستقلة أو SQLite محلية للتطبيق المحمول؛ جميع العمليات تُسجل مباشرة في قاعدة بيانات PostgreSQL المركزية للصيدلية.
2. **واجهة برمجية موحدة (REST API & Socket.IO)**: يستخدم التطبيقان نفس المسارات ونفس قواعد التحقق ونفس أحداث المزامنة الحية.
3. **تكامل كامل للمسؤوليات (Role-Based & Attribution)**: كل عملية تتطلب التحقق من هوية الموظف المنفذ عبر الرمز السري (PIN) ورقم تعريفه، مما يضمن تسجيل المسؤول عن كل أمر شراء أو استلام.
4. **تحديث لحظي عبر المنصات (Realtime Sync)**: عند تسجيل طلب نواقص جديد من محطة سطح المكتب، يظهر فوراً على شاشة هاتف مسؤول المشتريات دون الحاجة لإعادة تحميل الصفحة.

## 2. إعدادات الاتصال والوصول عن بُعد (Remote Access & Networking)

التطبيق غير مقيد بعنوان خادم ثابت (`localhost`)، بل يحتوي على شاشة إعدادات مدمجة (`ServerSettingsDialog`) تتيح تغيير العنوان واختبار الاتصال مباشرة من واجهة التطبيق.

### سيناريوهات الاتصال المدعومة:

| البيئة | عنوان API المقترح | الملاحظات |
| :--- | :--- | :--- |
| **محاكي أندرويد (Android Emulator)** | `http://10.0.2.2:4000/api` | العنوان الافتراضي للمحاكي للوصول إلى الجهاز المضيف. |
| **شبكة الصيدلية الداخلية (Local Wi-Fi)** | `http://192.168.1.XXX:4000/api` | يتم إدخال عنوان IP الخاص بجهاز السيرفر داخل الصيدلية. |
| **الاتصال الخارجي / الإنتاج (Production HTTPS)** | `https://pharmacy.yourdomain.com/api` | الوصول الآمن عبر الإنترنت المشفر (Cloudflare / Nginx Reverse Proxy). |

### اختبار الاتصال من داخل التطبيق:
- يمكن النقر على أيقونة الترس (⚙️) في شاشة تسجيل الدخول لفتح نافذة إعدادات الخادم.
- يتوفر زر **"اختبار الاتصال بالخادم"** للتأكد من وصول التطبيق إلى مسار `/api/health` قبل محاولة الدخول.
- يتم حفظ العنوان المختار محلياً في `SharedPreferences` بحيث يتذكره التطبيق تلقائياً عند إعادة الفتح.

## 3. الشاشات وسير العمل (Screens & Features)

### 1. شاشة تسجيل الدخول (`LoginScreen`)
- تسجيل الدخول بواسطة اسم المستخدم وكلمة المرور.
- إمكانية تحديد اسم الجهاز أو المحطة (مثل: `تطبيق أندرويد - مسؤول المشتريات`).
- حفظ الرمز المميز (JWT Token) وبيانات الجلسة بأمان عبر `FlutterSecureStorage`.
- دعم الخروج التلقائي عند انتهاء صلاحية الجلسة (401 Unauthorized Interceptor).
- أزرار دخول سريع للحسابات التجريبية لتسهيل الفحص والتجربة.

### 2. لوحة التحكم والإحصائيات اللحظية (`DashboardScreen`)
- مؤشرات عددية فورية لحالات النواقص:
  - إجمالي الطلبات
  - طلبات جديدة (`NEW`)
  - بانتظار الشراء (`REVIEWED`)
  - تم الطلب من المورد (`ORDERED`)
  - مستلم جزئياً (`PARTIALLY_RECEIVED`)
  - جاهز للتسليم (`RECEIVED`)
- شارة حالة الاتصال اللحظي (نقطة خضراء "متصل لحظياً" تتابع حالة Socket.IO).
- أزرار الوصول السريع للأقسام الرئيسية.
- شريط متابعة آخر الأنشطة والعمليات التي تمت في الصيدلية.

### 3. شاشة استعراض النواقص وتفاصيلها (`RequestsListScreen` & `RequestDetailScreen`)
- بحث فوري بالاسم التجاري للدواء، رقم هاتف العميل، أو رقم الطلب (`REQ-XXXXXX`).
- أشرطة تصفية أفقية حسب الحالة (الكل، جديد، تمت المراجعة، تم الطلب، مستلم جزئياً، تم الاستلام، تم التسليم).
- بطاقات أصناف أنيقة توضح الكمية المطلوبة والمستلمة، بيانات العميل، ودرجة الأولوية (عاجل/طوارئ).
- شاشة تفاصيل كاملة تتضمن:
  - شريط تقدم استلام الكميات (`LinearProgressIndicator`).
  - بيانات العميل مع إمكانية نسخ رقم الهاتف بلمسة واحدة.
  - الجدول الزمني الكامل لتتبع تحولات الحالة (`Status History Timeline`) مع اسم الموظف المنفذ وملاحظات كل مرحلة.

### 4. سير عمل طلب الصنف من المورد (`MarkOrderedDialog`)
- مخصص لمسؤول المشتريات لتأكيد طلب الصنف من شركات الأدوية.
- إدخال اسم المورد أو رقم أمر الشراء أو ملاحظات التسليم المتوقع.
- نافذة طلب الرمز السري (`PIN Confirmation`) لتسجيل العملية باسم الموظف.
- إرسال طلب `PATCH /api/orders/items/:id/status` وتحويل الحالة إلى `ORDERED` مع إرسال إشعار لحظي لباقي الأجهزة.

### 5. سير عمل استلام الشحنات بالصيدلية (`ReceivingScreen`)
- عرض قائمة الأصناف المطلوبة والمعلقة التي لم تكتمل كمياتها.
- إمكانية اختيار الصنف وتحديد الكمية المستلمة بدقة باستخدام أزرار التحكم (+ / -).
- التحقق الرياضي الصارم:
  - لا يمكن استلام كمية أكبر من الكمية المتبقية.
  - إذا كانت الكمية المستلمة أقل من المتبقي، تتحول الحالة تلقائياً إلى **مستلم جزئياً (`PARTIALLY_RECEIVED`)**.
  - إذا اكتملت الكمية بالكامل، تتحول الحالة تلقائياً إلى **تم الاستلام (`RECEIVED`)** لتصبح جاهزة لتسليم العميل.
- إدخال ملاحظات الفاتورة والتحقق من الرمز السري (PIN) للموظف المستلم.

### 6. شاشة سجل الأنشطة والعمليات (`ActivityScreen`)
- عرض السجل الأمني والرقابي لجميع العمليات المنفذة في النظام.
- اسم الموظف المنفذ، توقيت العملية الدقيق، ونوع الإجراء باللغة العربية.

## 5. أوامر البناء والتشغيل (Build & Run Commands)

### تشغيل التطبيق على محاكي أو جهاز متصل:
```powershell
cd pharmacy-mobile
flutter run
```

### تشغيل الاختبارات الآلية (Unit & Widget Tests):
```powershell
cd pharmacy-mobile
flutter test
```

### فحص الكود (Static Analysis):
```powershell
cd pharmacy-mobile
flutter analyze
```

### بناء حزمة APK للأندرويد:
```powershell
# بناء نسخة تصحيح الأخطاء (Debug APK):
cd pharmacy-mobile
flutter build apk --debug

# بناء نسخة الإنتاج النهائية (Release APK):
cd pharmacy-mobile
flutter build apk --release
```
يتم إنشاء ملف الـ APK النهائي في المسار:
`pharmacy-mobile/build/app/outputs/flutter-apk/app-release.apk` (أو `app-debug.apk`).
